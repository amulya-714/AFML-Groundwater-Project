# Reproducibility Guide

## 1. Project

**Why Do Groundwater ML Models Fail Under Extreme Conditions? Separating Input Extrapolation from Predictive Relationship Instability.**

This guide describes how to set up the Python environment, execute the main experimental scripts and locate their outputs.

## 2. Requirements

- Python 3
- pip
- Git
- The processed groundwater dataset
- The dependencies listed in `requirements.txt`

## 3. Repository Setup

Clone the repository:

```bash
git clone https://github.com/amulya-714/AFML-Groundwater-Project.git
cd AFML-Groundwater-Project
```

Create a virtual environment:

```bash
python3 -m venv .venv
```

Activate it on macOS/Linux:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## 4. Dataset

The main processed dataset is:

```text
data/processed/groundwater_rainfall_features_qc.csv
```

All main modelling scripts expect this dataset to be available at that location.

The target variable is:

```text
Groundwater Level Quarterly Manual (meter)
```

The chronological split is:

- Training: before 2018-01-01
- Testing: from 2018-01-01 onward

Do not change the split when reproducing the reported experiments.

## 5. Running the Experiments

Run all commands from the repository root with the virtual environment activated.

The experiments are grouped by their input dependencies. Some analyses are independent and do not need to be run in a strict order.

### A. Baseline model

Run the baseline first:

```bash
python src/baseline_model.py
```

Outputs:
- `results/baseline_metrics.csv`
- `results/baseline_predictions.csv`

The baseline predictions are required by several supplementary and temporal analyses.

### B. Independent input-novelty analyses

These analyses use the processed dataset directly.

```bash
python src/input_extrapolation_analysis.py
python src/compare_novelty_types.py
python src/within_well_novelty_analysis.py
```

Outputs include:
- `results/input_extrapolation_observations.csv`
- `results/input_extrapolation_summary.csv`
- `results/novelty_type_observations.csv`
- `results/novelty_type_summary.csv`
- `results/within_well_novelty_observations.csv`
- `results/within_well_novelty_summary.csv`
- `results/within_well_novelty_per_well.csv`

### C. Controlled training-removal experiment

Run after the processed dataset is available:

```bash
python src/controlled_training_removal.py
python src/controlled_removal_bootstrap.py
```

The bootstrap script requires `controlled_removal_predictions.csv`, generated by the first script.

Outputs:
- `results/controlled_removal_predictions.csv`
- `results/controlled_removal_metrics.csv`
- `results/controlled_removal_support.csv`
- `results/controlled_removal_bootstrap.csv`

### D. Temporal analyses

The following analyses use `results/controlled_removal_predictions.csv`. Run the controlled training-removal experiment first.

```bash
python src/paired_temporal_stability.py
python src/analyze_paired_temporal_distribution.py
python src/temporal_error_by_novelty.py
python src/temporal_distribution_comparison.py
python src/within_well_temporal_stability.py
python src/multivariate_temporal_residual_test.py
python src/temporal_residual_sensitivity.py
```

Important dependencies:

- `analyze_paired_temporal_distribution.py` requires `paired_temporal_well_errors.csv`, generated by `paired_temporal_stability.py`.
- `within_well_temporal_stability.py` generates `within_well_temporal_observations.csv`, which is used by the matched-input analysis below.
- The temporal regression scripts require `statsmodels`.

### E. Matched-input temporal analysis

Run after `within_well_temporal_stability.py`:

```bash
python src/within_well_matched_input_analysis.py
python src/within_well_clustered_bootstrap.py
python src/matched_input_temporal_analysis.py
```

The bootstrap requires `within_well_matched_input_pairs.csv`, generated by the matched-input analysis.

Outputs:
- `results/within_well_matched_input_pairs.csv`
- `results/within_well_matched_input_summary.csv`
- `results/within_well_clustered_bootstrap.csv`

### F. Conditional residual and paired temporal analysis

Run:

```bash
python src/conditional_residual_analysis.py
python src/paired_temporal_bin_test.py
```

The second script requires `conditional_residual_observations.csv`, generated by the first.

### G. Within-well paired novelty analysis

Run after `within_well_novelty_analysis.py`:

```bash
python src/within_well_paired_test.py
python src/within_well_bootstrap.py
```

The bootstrap requires `within_well_paired_test_per_well.csv`, generated by the paired test.

These scripts provide additional baseline error, support and extreme-error investigations.

After running the baseline model:

```bash

python src/investigate_extreme_errors.py
```

### Execution notes

- Run scripts from the repository root.
- Generate prerequisite CSV files before running dependent scripts.
- Do not assume that all scripts use identical eligibility criteria or evaluation samples.
- Existing result files should not be treated as proof that an experiment has been reproduced. Re-run the corresponding scripts when reproducing the results.

## 7. Reproducibility Considerations

- Use the same processed dataset.
- Preserve the chronological training/testing split.
- Keep the model hyperparameters unchanged when reproducing the baseline and controlled-removal experiments.
- Fit preprocessing transformations on training data rather than the test set.
- Do not use the final test set to fit novelty thresholds or model parameters.
- Preserve the random seeds specified in the scripts.
- Run dependent scripts in the required order.
- Do not compare results from experiments with different eligibility criteria as if they used identical samples.

## 8. Important Interpretation Notes

Novelty scores represent feature-space distances and should not automatically be interpreted as physical extreme events.

Environmental novelty and rainfall-only novelty are different definitions.

Temporal residual relationships indicate changes in prediction-error patterns but do not independently establish physical concept drift.

Bootstrap confidence intervals should be reported alongside point estimates when available.

## 9. Troubleshooting

### Virtual environment not activated

```bash
source .venv/bin/activate
```

### Missing Python dependency

```bash
python -m pip install -r requirements.txt
```

### Dataset not found

Check that the processed dataset exists at:

```text
data/processed/groundwater_rainfall_features_qc.csv
```

### Missing experiment output

Run the script that generates the required CSV before executing a dependent analysis.

### Check installed dependencies

```bash
python -m pip list
```

### Check Python version

```bash
python --version
```
